# Практическое занятие № 3. Пользователи, аутентификация и права доступа

Цель: освоить создание пользователей в СУБД, настройку аутентификации и разграничение прав доступа по принципу минимальных привилегий, а также блокировку учётных записей.

Среда: PostgreSQL 16 в Docker, база university, клиент psql.

## Подготовка

```sql
CREATE TABLE students (
    id SERIAL PRIMARY KEY,
    full_name VARCHAR(100),
    group_name VARCHAR(50),
    email VARCHAR(100),
    scholarship DECIMAL(10,2)
);

INSERT INTO students (full_name, group_name, email, scholarship) VALUES
    ('Иванов Иван', 'IT-23', 'ivanov@mail.ru', 50000),
    ('Петров Петр', 'IT-23', 'petrov@mail.ru', 45000),
    ('Сидорова Анна', 'IT-24', 'sidorova@mail.ru', 50000);
```

## Задание 1. Создание пользователей

```sql
CREATE USER student_user WITH PASSWORD 'Student_Strong_123!';
CREATE USER teacher_user WITH PASSWORD 'Teacher_Strong_123!';
CREATE USER db_admin WITH PASSWORD 'Admin_Strong_123!';

SELECT usename FROM pg_user;
```

Созданные пользователи:

- student_user — студент, только чтение
- teacher_user — преподаватель, чтение и изменение
- db_admin — администратор, управление пользователями и правами
- analyst_user — аналитик, только чтение (итоговое задание)

Аутентификация у всех по паролю.

## Задание 2. Настройка прав

```sql
GRANT CONNECT ON DATABASE university TO student_user;
GRANT USAGE ON SCHEMA public TO student_user;
GRANT SELECT ON students TO student_user;

GRANT CONNECT ON DATABASE university TO teacher_user;
GRANT USAGE ON SCHEMA public TO teacher_user;
GRANT SELECT, INSERT, UPDATE ON students TO teacher_user;

ALTER USER db_admin WITH SUPERUSER;
```

## Задание 3. Проверка прав

Подключился как student_user:

- SELECT * FROM students — разрешено, 3 строки
- UPDATE students SET scholarship = 100000 WHERE id = 1 — ERROR: permission denied for table students
- DELETE FROM students WHERE id = 1 — ERROR: permission denied for table students
- CREATE USER hacker — ERROR: permission denied to create role

Подключился как teacher_user:

- SELECT * FROM students — разрешено
- UPDATE students SET scholarship = 55000 WHERE id = 1 — UPDATE 1, проверил, стипендия стала 55000
- DELETE FROM students WHERE id = 1 — ERROR: permission denied for table students
- CREATE USER hacker — ERROR: permission denied to create role

Подключился как db_admin: SELECT работает, CREATE USER tmp_user и DROP USER tmp_user выполнились.

## Задание 4. Минимальные привилегии

Преподавателю нужно только смотреть студентов и менять оценки. INSERT ему не нужен, убрал:

```sql
REVOKE INSERT ON students FROM teacher_user;
```

После этого под teacher_user: INSERT — permission denied for table students, UPDATE по-прежнему работает. Это принцип Least Privilege: у пользователя ровно те права, которые нужны для работы.

## Задание 5. Блокировка пользователя

```sql
ALTER USER student_user NOLOGIN;
```

Попытка подключиться: FATAL: role "student_user" is not permitted to log in. Учётная запись и её права остались, но войти нельзя.

```sql
ALTER USER student_user LOGIN;
```

После этого подключение снова работает, SELECT current_user вернул student_user.

## Итоговое задание. Аналитик

```sql
CREATE USER analyst_user WITH PASSWORD 'Analyst_Strong_123!';
GRANT CONNECT ON DATABASE university TO analyst_user;
GRANT USAGE ON SCHEMA public TO analyst_user;
GRANT SELECT ON students TO analyst_user;
```

Под analyst_user:

- SELECT * FROM students — разрешено, 3 строки
- UPDATE students SET scholarship = 60000 WHERE id = 1 — ERROR: permission denied for table students
- DELETE — ERROR: permission denied for table students
- CREATE USER — ERROR: permission denied to create role

## Матрица прав

Пользователь — SELECT — INSERT — UPDATE — DELETE — управление пользователями

- student_user — да — нет — нет — нет — нет
- teacher_user — да — нет (отозвано) — да — нет — нет
- db_admin — да — да — да — да — да
- analyst_user — да — нет — нет — нет — нет

Подтверждение из \dp students:

```
student_user=r/postgres
teacher_user=rw/postgres
analyst_user=r/postgres
```

(r = SELECT, w = UPDATE)

## Результаты проверки

Разрешены: SELECT у всех; UPDATE у teacher_user; INSERT у teacher_user до REVOKE; любые операции у db_admin.

Запрещены: UPDATE и DELETE у student_user и analyst_user; DELETE и INSERT (после REVOKE) у teacher_user; CREATE USER у всех, кроме db_admin; вход под student_user после NOLOGIN.

Ошибки СУБД:

- permission denied for table students — нет права на операцию с таблицей
- permission denied to create role. Only roles with the CREATEROLE attribute may create roles — нет права создавать пользователей
- FATAL: role "student_user" is not permitted to log in — учётная запись заблокирована

## Вывод

Создал четыре учётные записи с парольной аутентификацией и разными уровнями доступа. Права выдаются через GRANT, лишние убираются через REVOKE, блокировка делается через ALTER USER NOLOGIN без удаления учётки. Проверка под каждым пользователем показала, что СУБД реально отказывает в запрещённых операциях. Студент и аналитик получили минимальные права, преподаватель — рабочие, администратор — полные.
