# Занятие 15. Безопасность, бэкап, итоговая работа

**Цель:** ограничить права, проверить защиту от SQL-инъекции, сделать и проверить бэкап; защитить итоговую работу.
**Go:** вместо `vuln_api.py` — `cmd/vuln/main.go` (уязвимая функция с конкатенацией) и `cmd/safe/main.go` (параметризованная), `pgx`.

## Структура
```
15-security-backup-final/
  sql/01_roles.sql           # app_reader, app_writer
  sql/02_checks.md           # таблица проверок ролей
  cmd/vuln/main.go           # УЧЕБНАЯ уязвимость, только локально!
  cmd/safe/main.go           # исправленная версия ($1, $2)
  backup/                    # *.dump, restore-лог, подсчёт строк
  FINAL.md                   # итоговая работа: схема, функции, индекс, ответы
```

## Часть 1. Роли и права
- `app_reader` (LOGIN, пароль из env): `SELECT` на 4 таблицы.
- `app_writer`: + `INSERT/UPDATE` на `checkout_facts`, `INSERT` на `titles` (+ `USAGE` на sequence). `DELETE` и DDL — запрещены обеим.
- Под каждой ролью: SELECT, INSERT, DELETE, DROP TABLE, CREATE TABLE → записать `permission denied` в таблицу проверок.

## Часть 2. SQL-инъекция (⚠ только своя учебная БД)
- `cmd/vuln`: подобрать ввод: (а) вернуть все строки; (б) `UNION` → список ролей сервера (`pg_roles`).
- Заменить на параметризованный запрос, повторить.
- Подключить vuln под `app_reader`, попробовать `DROP TABLE`. Вывод: права ограничивают ущерб (DROP не пройдёт), но чтение чужих данных через UNION возможно — защищает только параметризация.

## Часть 3. Резервная копия
```
pg_dump -Fc -f seattle_library.dump seattle_library
createdb seattle_restore
pg_restore -d seattle_restore seattle_library.dump
```
Числа строк в 4 таблицах → дамп → «авария» (DROP таблицы) → восстановление в новую БД → сравнить числа.
