# Занятие 14. Заметки

Запуск:
```
set -a; . ../08-web-api/.env; set +a
export API_KEY='<свой ключ>'
go run .
```
Страница клиента: `http://127.0.0.1:8000/` (ключ вводится в поле на странице). Go-клиент: `API_KEY=... go run ./cmd/client -q "love story"`. Postman: `postman/collection.json` (11 запросов, переменные `base_url`, `api_key`).

## Что сделано
| Требование | Реализация |
|---|---|
| Ключ `X-API-Key` на всех маршрутах данных | middleware `requireAPIKey` на группе маршрутов, ключ из env `API_KEY`, сравнение `subtle.ConstantTimeCompare`, нет или неверный → 401 |
| `format=json\|xml` | `/titles/top?format=…`, XML через `c.XML` (`encoding/xml`), другое значение → 422 |
| Поиск `/search?q=` | `q` не короче 2 символов (иначе 422), `to_tsvector('english', title) @@ phraseto_tsquery('english', $1)`, параметр передаётся через `$1` |
| Клиенты | `web/client.html` (fetch + заголовок ключа), `cmd/client` на Go |
| Страница без ключа | `GET /` вне группы с проверкой, данные только с ключом |

## Инъекция
`q=' OR 1=1 --` возвращает `[]`. Запрос параметризован, и Postgres разбирает строку как текст для поиска, а не как SQL. Я взял `phraseto_tsquery`, а не `plainto_tsquery`: `plainto` превратил бы `1=1` в слово `1` и вернул бы названия с цифрой 1 (не все строки, но и не пусто), а `phraseto` ищет слова подряд (`'1' <-> '1'`) и даёт пустой список.

## Почему ключ нельзя «зашить» в публичную страницу
HTML и JavaScript отдаются браузеру как есть, поэтому любой, кто откроет страницу, увидит ключ в исходном коде или во вкладке Network, и им сможет пользоваться кто угодно. В учебной работе мы принимаем это ограничение: ключ вводится вручную в поле. В реальном приложении ключ держат только на сервере, а браузеру выдают пользовательские сессии или короткоживущие токены.
